# EasyCanpusRun-ECR · 长沙工业学院跑步轨迹注入

把 GPS 坐标按 1 Hz 喂进雷电模拟器，让里面的**运动世界**认为你在操场上跑圈。

仓库里只有工具。模拟器、运动世界、摄像头，这些你自己装好，本仓库不发安装包，也不带你装。

> 仓库地址：<https://github.com/Nyacchan/EasyCanpusRun-ECR>
>
> CCSUT 长工限定

---

## 它到底做什么

就三件事，别的一概不做：

1. **生成轨迹**：按本校第 3 道（一圈 421.36 m）的几何 + 配速曲线 + GPS 噪声，算出一条像人跑出来的点序列
2. **注入**：每秒一个点写进虚拟机的定位服务（`ldconsole locate`），没有 mock 标记
3. **可选诊断**：判断模拟器里的相机画面是电脑摄像头，还是内置合成场景

不修改运动世界的安装包，不用 Xposed 改相机数据，不提供静态照片过人脸比对的方案。

## 三步跑起来

```text
① 装 Python 3.10+ 和 Node.js 16+，都加到 PATH
② 启动雷电 9，等它进安卓桌面，模拟器里运动世界能正常打开
③ 双击「一键刷跑.vbs」（无黑框）→ 里程 2110、配速 8'20" → 点「开始跑」
```

界面左边是跑道图，小圆点就是当前喂进去的位置；右边是日志，每投喂一次写一行。

跑完点停止，会问你「原地停」还是「回到起点」。回起点是为了下一趟干净。

## 默认参数（长沙工业学院）

代码里这些是写死的，因为全校就一个操场：

```python
CENTER_LAT, CENTER_LNG = 28.345304, 112.794749   # 操场中心（WGS-84）
LANE_R   = 40.2      # 第 3 道半径（米）
STRAIGHT = 84.39     # 直道长（米）
LAPS     = 5         # 5 圈 ≈ 2106.8 米
PACE_SEC = 500       # 配速 8'20"/公里（学校要求不慢于 8'30"，留 10 秒余量）
```

| 项 | 值 | 依据 |
|---|---|---|
| 单次跑量 | 2110 m（5 圈） | 学校要求的 2.1 km，按整圈取整实际 2106.8 m |
| 配速 | 8'20" | 学校要求不慢于 8'30"；默认给 10 秒余量，想贴线就填 8'30" |
| 跑道中心 | 28.345304, 112.794749 | 高德 GCJ-02 的 28.341922, 112.800297 转换过来 |

学校通知变了就改这三个数：`LAPS`（圈数）、`PACE_SEC`（配速）、`CENTER_LAT/LNG`（换校区才动）。

**改配速的换算**：8'30" = 510 秒；8'20" = 500；8'00" = 480；7'30" = 450。填的是「每公里多少秒」，不是速度。

**不在长沙工业学院？** 换成你们学校要改哪几个数、操场怎么量、圈数和配速怎么算，全在 [`换学校.md`](换学校.md)。

## 坐标系（最容易踩的坑）

运动世界这类 App 用 **GCJ-02（火星坐标）**，模拟器的定位注入要 **WGS-84**。

同一个地方，两者差约 **500 m**，直接喂 GCJ 坐标会得到「不在围栏内」或者成绩无效。

```text
GCJ-02  112.800297, 28.341922
WGS-84  112.794749, 28.345304      实际相差约 506 m
```

本仓库所有坐标都是 WGS-84，直接用。你要是从手机地图复制的坐标，先转成 WGS-84，
方法见 [`技术原理.md`](技术原理.md) 第 3 节。

## 出问题了先看这几条

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 提示「不在围栏内」 | 坐标系没转 | 换成 WGS-84 的坐标 |
| 位置一直不动 | 没连上模拟器 | 先跑 `python doctor.py`，看它说缺什么 |
| `adb devices` 是空的 | ADB 没开 / 不是桌面图标启动 | 关掉雷电，用桌面图标重开，确认 ADB 调试已开 |
| 相机画面发青、没细节 | `ldcam.exe` 占着设备不送帧 | 结束 `ldcam.exe`，重启模拟器，跑 `检查相机.bat` 复查 |
| 运动世界提示定位异常 | 风控 | 这个躲不掉，见下面的风险 |

细节都写在 [`使用方法.md`](使用方法.md)。

## 已知限制

1. **相机比例**：4:3 档位被横向压缩 18.5%（640×480 是 1280×720 压来的），用人脸比对时要注意，补偿方案见 `技术原理.md` 第 5 节
2. **相机稳定性**：`ldcam.exe` 偶尔占着摄像头不送帧，表现为画面变淡青色
3. **传感器缺失**：模拟器没有 `TYPE_STEP_COUNTER`，界面上的步频/步数/步幅是按配速反推的展示值，不是真传感器读数
4. **只接管雷电 9**：程序会跳过路径含 `LDPlayer14` 的实例，用环境变量 `LDCONSOLE` 强行指过去可以绕过这个保护，但没必要

## 风险，说在前头

这个工具只解决「坐标从哪来」，**不解决风控**。

前一个校园跑平台（悦跑世界 1.1.23）上，同一套模拟器方案已经走到过终点：2026-11-01 到 11-03 有整批账号在同一时段被封，跑量 6 次和 8 次的人一起中招，都是「第一次跑完正常，第二次点开始跑被拒」。查出来是服务端按**环境类别**批量筛的，跟轨迹随机化、步频伪造得多真无关。

当时查到的检测项，运动世界大概率也有同一类东西：

- 设备指纹 SDK，native 层读 `/proc/self/maps` 扫内存映射，Xposed、LSPosed、frida 一注入就露
- dex 层硬编码检测 root、Magisk、Xposed、`isFromMockProvider`
- 只有 `arm64-v8a` 的 so，没有 x86，模拟器靠 ARM 转译这本身就是特征
- 步频步幅是明确判定项，模拟器没有 `TYPE_STEP_COUNTER`，这项必然异常
- 围栏可以开「本人检测」，要摄像头加人脸，虚拟摄像头过不了
- 会检测网络代理，宿主机开代理也可能命中
- **平台会定期复核历史记录**，不是当场拦，所以「跑完看着正常、过两天才被封」很常见

学校《使用注意事项》原文也写着：手机运行虚拟软件、root、分身双开都会触发防作弊机制，平台定期复核历史有效记录，涉及账号安全的作弊会封号，永久封禁要经校方授权才能解封。

想少踩一点，能做的只有：里程、配速、时段每次变一变，两次之间隔开，一个账号别在多环境里来回切。这是降低概率，不是免死金牌。

还有一层：学校对跑步的要求是体育课的一部分，用工具代替真跑，被查出来是**校纪层面**的麻烦，不只是封个号。

知道自己担什么，再决定用不用。用了就自己担。
